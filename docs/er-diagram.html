Doctor appointment system

Eight entities: the seven from the hand-drawn sketch plus Device. Patients and doctors are both users, each user can log in on several devices, doctors belong to departments, and patients book appointments with doctors through schedule slots.

Read from the sketch

  • User is the shared login. A patient, a doctor or the registrar is each a kind of user, so both is a links are one-to-one.
  • Device (new) records each phone a user signs in from: its name, platform, push token and last login. One user can have many devices.
  • Phone Number is its own table with a patientId, so one patient can keep several numbers.
  • Schedule holds the time, date and place. Its doctorId and patientId point to Doctor and Patient.
  • Appointment keeps the serial number, the login phone (patientPhone) and the device it was booked from (deviceId), plus name, age, doctor name, date and time. My Appointments lists bookings by phone number.

What I added or guessed

  • Fields marked * were not in the sketch: an id on Schedule, Appointment, Doctor and Department, and departmentId on Doctor so the department link has a key.
